Round 2 (review fix): Codex found three holes in the recovery (raid_walk_phases.go recoverWipe /
recoverNearWipe / restOutOfCombat). Decisions from the brief:
1. Fail closed on unknown boss state: recovery only when boss evidence is FRESH (last good
   dashboard fights/boss read <= 30 s old and no engaged boss). No dashboard, stale (> 30 s),
   or errored read -> no recovery: end exactly as before K (exit 19 wipe / old paused ending)
   with note "wipe resume skipped: boss state unknown". A boss latched in the last 120 s also
   blocks recovery (old path / handleBoss).
2. Quiet = a complete fresh view, polled: restOutOfCombat polls bot_view every 5 s. A poll counts
   only if the call succeeded AND every roster hire is present, row <= 10 s old, not in combat,
   not dead. Any failed call, missing/stale hire, combat or dead restarts the quiet window from
   zero. Near-wipe dead-hire counting needs the same complete view; none within 60 s -> old
   ending + note "wipe resume skipped: no complete bot view".
3. Absolute deadline: recovery gets min(walk max-run ceiling, recovery start + 3 x --wipe-rest).
   Combat restarts the quiet window but never the deadline. Past it -> the ORIGINAL incident's
   exit (19 / old paused code) + note "wipe recovery timed out after <dur>". The 60 s running-
   line wait stays inside the deadline.
